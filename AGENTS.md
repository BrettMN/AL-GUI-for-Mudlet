# AGENTS.md

## Project Overview

Mudlet UI package built with [Muddler](https://github.com/demonnic/muddler) — a Gradle-based build tool that compiles a structured source tree into `.xml` + `.mpackage`. Lua 5.1 runtime inside Mudlet client. UI via Geyser layout manager.

---

## Tech Stack

| Layer | Detail |
|---|---|
| Runtime | Mudlet (Lua 5.1 embedded) |
| Build tool | Muddler (`muddle` CLI — fat JAR, requires Java 8+) |
| UI framework | Geyser (Mudlet built-in OOP layout manager) |
| Package format | `.mpackage` (ZIP) — produced by Muddler in `build/` |
| Item config | JSON files per folder (mirrors Mudlet UI options) |
| Testing | `busted` for unit tests; manual install/uninstall cycle for integration |

run C:\Programs\Muddler\bin\muddle.bat in the `alui` folder to build the package. Output lands in `build/`.

---

## Project Structure

Muddler uses **convention over configuration**. Do not deviate from this layout.

```
alui/
├── mfile                   # JSON — package metadata (name, version, author)
├── build/                  # OUTPUT ONLY — never edit; regenerated on each muddle run
│   ├── <PackageName>.xml
│   └── <PackageName>.mpackage
└── src/
    ├── aliases/
    │   └── <GroupName>/
    │           aliases.json
    │           <alias>.lua
    ├── keybindings/
    │   └── <GroupName>/
    │           keybindings.json
    │           <keybinding>.lua
    ├── resources/
    ├── scripts/
    │   └── <GroupName>/
    │           scripts.json
    │           <module>.lua
    ├── timers/
    │   └── <GroupName>/
    │           timers.json
    │           <timer>.lua
    └── triggers/
        └── <GroupName>/
                triggers.json
                <trigger>.lua

```

> **GroupName** becomes the parent item name in Mudlet's editor. Nesting deeper subdirectories creates nested groups.

## mfile

`mfile` is a JSON file in the project root. Minimum required field is `package`.

```json
{
  "package": "MyPackageName",
  "version": "1.0.0",
  "author": "YourName",
  "title": "My Mudlet UI",
  "description": "What this package does."
}
```

`@PKGNAME@` and `@VERSION@` tokens in Lua files are substituted at build time with these values.

## Build Commands

```bash
# Build package (run from project root)
muddle

# Scaffold a new project interactively
muddle --generate

# Scaffold with all defaults (good for CI/testing)
muddle --default
```

Output lands in `build/` — both `.xml` (importable) and `.mpackage` (distributable).

```lua
-- Reload inside Mudlet console during development
lua uninstallPackage("MyPackageName"); installPackage("/path/to/build/MyPackageName.mpackage")
```

## JSON Config Files

Each `src/<type>/<Group>/` folder has one `<type>.json` that describes all items in that group. Fields mirror Mudlet UI options. Example `triggers.json`:

```json
[
  {
    "name": "HP Trigger",
    "type": "substring",
    "pattern": "You have (\\d+) health",
    "isActive": true,
    "isFolder": false,
    "script": "hp_trigger.lua"
  }
]
```

Items are **parent→child** via nesting in the JSON array, matching Mudlet's tree structure.

## Coding Conventions

- Lua 5.1 only — no `goto`, no bitwise operators without `bit` lib, no `<const>`.
- All modules return a table: `local M = {} ... return M`. No bare globals.
- Use `@PKGNAME@` token (not hardcoded string) to reference package name in Lua.
- Use `cecho`/`decho`/`hecho` for console output — not `print`.
- Event handlers: `<Module>.<action>Handler` naming (e.g., `HP.onChangeHandler`).
- UI Geyser objects: create inside `sysLoadEvent` handler, never at bare module load time.
- `resources/` — place any non-Lua assets here; Muddler bundles them into the `.mpackage`.

## Boundaries

### ✅ Always
- Run `muddle` and do a full install/uninstall cycle after any JSON or Lua change.
- Keep Lua logic in `.lua` files; keep `.json` files for metadata only.
- Use `@PKGNAME@` / `@VERSION@` tokens where package identity is needed.
- Commit `mfile` and all `src/` — never commit `build/` (add to `.gitignore`).

### ⚠️ Ask First
- Adding new Mudlet event listeners (check for name collisions across packages).
- Adding new `<GroupName>` subdirectories (affects Mudlet editor tree structure).
- Adding third-party Lua libraries (no `require()` — Muddler controls load order via XML).

### 🚫 Never
- Edit anything in `build/` — it is fully regenerated by `muddle`.
- Use `require()` for project-internal modules — Muddler load order via XML handles this.
- Define functions inside trigger/alias/timer script bodies — put them in `src/scripts/`.
- Hardcode pixel sizes in Geyser — use percentage-based sizing.
- Put non-Lua source files outside `resources/` expecting them to be bundled.
